## Areas needing a maintainer

Honestly stated, because a project that pretends to have full coverage gets bugs it
never sees. If one of these is your area, this is an open invitation:

| Area | What is missing |
|---|---|
| **Adapters** | Nobody owns adapter breadth. New agent frameworks appear faster than we add support. |
| **Reporting & leaderboard** | The reporting pipeline needs an owner with opinions about presentation. |
| **A2A / MCP surfaces** | Both protocols move quickly; keeping conformance current is real ongoing work. |
| **Corpus — storage & networking** | `DATA` and `PERF` coverage is thin because neither maintainer is a storage specialist. |
| **Corpus — real site data** | We want someone from a facility other than CINECA. |
| **Windows / macOS support** | Tested on Linux; other platforms get no systematic attention. |

See [GOVERNANCE.md](GOVERNANCE.md) for how maintainership works. Asking is fine.

## Response expectations

- **First response within 3 working days**, even if it is only "seen, I'll look
  properly on Friday".
- **If a PR of yours goes quiet for over a week, ping it.** That is our failure, not
  rudeness on your part.
- **Security reports:** see [SECURITY.md](SECURITY.md) — do not open a public issue.

## Emeritus

None yet. Maintainers who step back are listed here with thanks, and their
